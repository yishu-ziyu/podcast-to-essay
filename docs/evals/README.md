# 验收与测试记录

两类文件，文件名以日期开头：

- **验收契约** `YYYY-MM-DD-<主题>.md`：做一件较大的事之前写。要改变什么、什么不算完成、谁来判断、需要什么证据。例：[公网媒体导入可靠性](2026-09-22-public-media-pipeline-reliability.md)。
- **端到端记录** `YYYY-MM-DD-e2e-<主题>.md`：每次改动用户流程后，在真实界面用真实输入走一遍，记录下来。

## 端到端测试怎么做

真实路径优先：打开真实界面，粘贴真实链接、上传真实文件，看识别、进度、报错、恢复。拦截请求或伪造数据的检查只作辅助证据。

每次至少覆盖受影响的流程，输入从下面挑：

| 类型 | 例子 |
|---|---|
| B 站视频 | `https://www.bilibili.com/video/BV…`、`b23.tv` 短链 |
| YouTube | `youtube.com/watch?v=…`、`youtu.be/…` |
| 抖音 | 分享口令整段文字（链接夹在中文里）、`v.douyin.com` 短链、用户主页（应被拒） |
| 播客页面 / 媒体直链 | 小宇宙单集页、`.mp3` 直链 |
| 陌生与错误输入 | 普通网页、平台首页、内网地址、不带协议的文字 |
| 本地文件 | 短音频、视频文件、非媒体文件（应被拒） |

转录和整理会消耗 StepFun 额度：用短素材；测完在界面里删掉测试条目。游客模式和所有者模式都要看。
