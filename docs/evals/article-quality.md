# 文章质量记录

每读完一篇生成的文章，对照原稿记一条：**过 / 不过 + 一句理由**。方法来自 Hamel Husain 的 evals 做法：先靠人读、积累真实的失败理由，再把能用代码检查的理由变成自动检查。

## 规则

- 只写「过」或「不过」，不打分。理由写具体的一件事：「漏了第三个观点」「编了原稿没有的数字」「小标题和内容对不上」。
- 能指出原稿位置就写上（分段稿的段号或时间戳）；写不出也没关系。
- 攒到 20–30 条后归类：数一数每类理由出现几次，挑出现最多、又能用代码判断的，先写成检查（例如「文章里的数字必须出现在原稿里」「段落映射不能为空」），记入 [../backlog.md](../backlog.md)。
- 暂不做：LLM 评委、看板、打分制。等人工记录说明需要时再说。
- 换模型或改整理提示词后，重读几篇已记录的素材，对照之前的结论。

模板（新的写在最上面）：
